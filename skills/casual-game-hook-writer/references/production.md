# 视频提示词与工具执行

## 阶段与输入

先定位用户选定版本、最新修改与分镜编号，继承已确认的时长、画幅、人物、风格、台词、音效和绿幕要求，不重新改创意或混合两版。

现有提示词要求优化时无需先选脚本，直接在既有输入上工作。用户只要提示词时到可复制文本为止；明确要求生成才提交任务。已在上下文授权的同一范围不反复确认。

## 提示词组织

每个独立提示词应包含：时长/画幅与必要风格；稳定的人物、道具、位置和初始画面；随时间发生的动作及结果；景别/视角/运镜；结束状态与下一段交接；声音意图和少量关键约束。

中文沟通时默认给可复制中文提示词，按用户/工具真实要求适配语言；广告台词保留目标语言原文。说明语言与广告语言是两件事，不因给英文提示词就把所有广告字幕改为英文。

每段独立复制也能使用，不能只写「同上」。多段保留身份、服装、道具、光线与空间关系；有参考图片时沿用真实引用，不虚构上传成功。解释、心理机制、测试指标和后期备注放在提示词之外。

### 提示词输入的优化检查

- 创意问题：开场是否有明确事件、观众看得懂什么、动作如何引起后果、如何接玩法。
- 表达问题：主体或代词是否歧义，人物/道具是否前后冲突，时间和动作是否挤在一起。
- 制作问题：要求是否匹配目标工具的真实能力，必要参考是否可用，屏幕绿幕和声音意图是否遗漏。
- 约束保留：不能把用户指定人物、台词、风格、镜头或模型随意替换；重构版仍保留核心 idea。

保守版与增强版都交付完整可复制文本，不只列修改建议。用户明确只改一句或只要一版时按该范围交付。

### 含手机屏幕的固定要求

每个相关片段正文写清：

> 手机屏幕显示区域为均匀纯绿色绿幕，供后期替换；保留手机边框和机身，人物与环境正常呈现。屏幕内无游戏画面、无 App UI、无文字或图标。

英文提示词用等义要求。不能只在可选备注写 green screen。可选备注：「后期替换为用户提供的箭头解谜录屏，保持与上一镜的移动方向一致。」不需备注时省略这句，正文绿幕不能省略。

## 从分镜到模型片段

区分叙事分镜、模型生成片段和最终合成。模型片段受单段时长、参考/身份能力和声音能力限制；最终合成还可能用真实玩法与后期字幕/声音。

工具能可靠接受所需时间线时可整段提交，否则按动作和交接点分段，说明连续性计划；不为适配模型省掉关键事件。单段原子文生视频不等于多镜头叙事/人物一致性工作流。只有用户明确接受粗样时才用低保真替代，并说明限制。

## 工具选择

1. 用户指定工具/模型优先。
2. 未指定时优先 Video Lab，其次即梦；不反复询问已确定的偏好。
3. 已指定工具不可用时，先交提示词/执行计划，说明具体障碍，提出备选；不静默换工具/模型或降质。
4. 工具/模型/参数/价格以执行时的帮助、workflow contract 或 authoring-contract 为准，不维护静态型号表。

本 skill 不自带视频服务。脚本/提示词独立可用；实际生成依赖相应 CLI、登录态及执行技能。

## Video Lab

定位并读取当前安装的 `video-lab-generation-router`，再加载它选择的 owning skill。不能虚构 `video-lab vimax` 等子命令。

- 单一原子片段、无跨镜头连续性：`video-lab-cli-text-to-video`。
- 多镜头故事/人物连续性：按路由使用 `video-lab-vimax-idea2video-script2video-harness` 和所需配套技能。
- 用户必须使用的图片/身份参考：走 router 的相应路径，不丢掉必需参考改成纯文本。

读取当前 workflow contract；需要选模型/高级字段时读取 authoring-contract。参数使用文件或安全的结构化方式传递，先 dry-run 通过再创建真实任务。

记录 task id，按确切 id 等待和查询。网络不确定时先查已有任务，不盲目重复创建；不在用户范围之外追加候选或付费重生。

现有 owning skill 的确切必需选项继续遵守，并说明具体技能及原因；已知选择可按其支持方式复用。不在本 skill 另加自创批准环节。缺少对应 CLI/技能时如实说明，继续交付提示词。

## 即梦

读取 `dreamina-cli`，用 `dreamina -h` 及所用子命令 `-h` 发现当前模型、时长、画幅、声音和参考能力，复用已有登录态。不把一条命令参数套到另一条，不默认某型号可用。

先说明真实任务可能消耗额度，在用户已有范围内执行，不重复索取同一授权。保存 submit_id，以当前 CLI 明确状态判断提交成功，再按该 id 查询。失败时交代原因、保留提示词及任务信息。

## 执行范围

提交前简短说明：选定稿、工具/已发现模型、几段、每段时长/画幅、声音、真实玩法是否尚待后期替换。有已知费用/额度时说明，未知时不编造。遵守既有预算、候选数和重试限制；确实缺少影响费用范围的决定时只问该项，脚本/提示词可先完成。

## 检查和交付

任务状态成功后继续取得实际视频，使用工具支持的预览/下载/媒体检查验证：

- 可打开，时长和画幅符合实际选择。
- 首帧、关键事件、末帧符合选定稿；必要时看中间动作，不只看缩略图。
- 人物与道具连续，关键动作未丢失或严重形变。
- 手机每次出现屏幕都保持绿幕，没有自动生成 UI，且仅屏幕区域为绿。
- 应有声音/台词是否实际存在；没有音轨不能称声音已完成。

只能查状态、无法观看时区分「任务成功」和「画面已验收」。约束失败时交付真实候选及具体问题/修正方案，不能称为合格终稿，也不未经授权无限重生。

优先内联可播放视频及真实文件/可用结果链接；不是只返回任务 ID。鉴权保护的 Video Lab 输出沿用其媒体下载流程，不用裸 URL 假装下载成功。绿幕前贴明确玩法尚需后期替换；只有真实玩法已取得、合成并检查后才称为玩法成片。
